# 승요 판독기: 당신은 승요가 맞다

야구팬(특히 KBO 직관러)을 위한 밈 서비스 기획/설계 문서.
아래 내용을 바탕으로 웹 서비스(Next.js)를 구현한다.

---

## 1. 서비스 컨셉

직관 간 날짜를 입력하면, 알고리즘이 "어떻게든" 승요(승리 요정) 조건을 찾아내는 서비스.
전승이면 그 자체로 승요, 일부만 이겼으면 **이긴 날에만 있고 진 날엔 전혀 없는 조건**을
날짜 계산·캘린더 미신·KBO 경기 데이터에서 억지로 찾아내 "무조건 승요"라고 선언한다.
직관을 다 졌으면 반대로 "이 조건만은 피하라"는 회피 조건을 찾아준다.

핵심은 **조건이 억지스러울수록(=표본이 작고 조건이 복잡할수록) 더 재밌다**는 것.
"통계적으로 신뢰도 낮음"을 부끄러워하지 않고, 오히려 "억지력/희귀도"로 자랑스럽게 드러낸다.

### 톤 & 무드 (중요)
- **"진지한 척하는 헛소리"** — 코미디의 deadpan(무표정) 구조. 서비스가 먼저 농담인 척하지 않는다.
- 판독 문구, 통계, 도장, 용어 전부 관공서/논문/영수증 같은 근엄한 형식을 유지한다.
  (예: "FORCED VERDICT", "공식 인증", "판독 보류", "AVOIDANCE VERDICT")
- 딱 **한 군데씩만** 뻔뻔한 반말/틱틱대는 문장("밸브")을 심어서 킹받음을 유발한다.
  (예: "그 외의 통계적 유의미성은 판독기의 알 바 아님.", "승요가 되기 위해서는 수련이 필요합니다.")
- 통통 튀는 이모지, 밝은 톤은 지양. 근엄함과 내용의 황당함 사이의 괴리가 웃음 포인트.

## 2. 사용자 플로우

```
1) 팀 선택 (KBO 10개 구단)
2) 직관 날짜 선택 (캘린더에서 다중 선택)
   - 실제 "경기가 열린 날"만 선택 가능해야 함 (비시즌 월은 선택 자체 비활성화)
   - 월 이동 가능
   - 디폴트로 펼쳐지는 월 = 오늘 날짜가 속한 월. 단, 오늘이 비시즌이면 어떤 월을
     기본으로 열지는 미정 (TODO, 아래 8.미정 사항 참고)
3) "판독하기" 버튼 → 알고리즘 실행
4) 결과 카드 노출 (4종 중 하나, 3장 참고)
5) 카드 이미지로 저장/공유 (클라이언트 캡처)
6) (선택) 기록 초기화 버튼 — 같은 기기에서 다른 사람이 다시 쓸 때, 날짜를 일일이
   해제하지 않고 한 번에 리셋하기 위함. 안내 문구 불필요.
```

## 3. 알고리즘 설계

### 3.1 전체 분기

```
무승부 경기는 분석에서 제외.
직관 경기 수(승+패, 무승부 제외) < 3  → "판독 보류" 화면
직관 경기 수 ≥ 3, 승 = 0            → 패배방지 모드 (진 날 공통 조건 = 회피 조건)
직관 경기 수 ≥ 3, 패 = 0            → 완전승요 (조건 불필요)
직관 경기 수 ≥ 3, 승 ≥ 1, 패 ≥ 1     → 부분승요 (조건 탐색)
```

### 3.2 피처 그룹

**A그룹 — 날짜 계산 + 캘린더 (API/크롤링 불필요, 항상 계산 가능)**
- 요일, 주말/평일 여부
- 월/일 홀짝
- 월+일, 월×일, 월-일, 각 계산값의 자릿수 반복합(수비학 스타일), 월일 이어붙인 숫자
- 위 계산값들에 특정 숫자(0~9)가 포함되는지 → **계산 소스별로 분리해서 피처화**
  (예: "월일덧셈_숫자4포함" / "월일곱셈_숫자4포함" / "자릿수합_숫자4포함" 을 별개 피처로 취급.
   합쳐서 "숫자4포함"으로 뭉치면 카피에 "어디서 4가 나온 거야?"라는 혼란이 생기므로 반드시 분리할 것)
- 팰린드롬(월일 대칭), 손없는날(근사치)

**B그룹 — KBO 경기 데이터 (실제 크롤링/API 필요, 데이터 소스는 개발 시점에 별도 확정)**
- 홈/원정, 상대팀, 구장, 시리즈차수, 직전 연승/연패 스트릭 여부
- (2차 확장 후보, 미구현) 낮/밤경기, 선발투수 좌/우, 날씨(기상청 API), 코스피 등락

### 3.3 카테고리 티어 (우선순위)

피처를 "사람이 얼마나 바로 공감하는가" 기준으로 4단계 티어로 나눈다.
숫자가 낮을수록 우선순위 높음(더 그럴듯함).

| 티어 | 카테고리 |
|---|---|
| 1 | KBO 경기조건: 홈원정, 구장, 상대팀, 시리즈차수, 선발투수, 연승연패, 낮밤경기 |
| 2 | 캘린더/미신: 요일, 주말여부, 손없는날, 월령 |
| 3 | 날짜 사칙연산: 월홀짝, 일홀짝, 월일덧셈, 월일곱셈, 월일차, 팰린드롬 |
| 4 | 숫자놀이: 월일자체숫자, 자릿수합, 월일이어붙임 (가장 추상적) |

### 3.4 탐색 알고리즘 (승요 조건 찾기)

```
목적: "이긴 날 중 일부(또는 전부)를 100% 설명하면서, 진 날엔 단 한 번도 등장하지 않는
      조건(피처 조합)"을 찾는다. 커버리지가 낮아도 예외가 0이면 그 조건이 이긴다
      (많이 맞는 조건이 아니라 한 번도 틀리지 않는 조건을 찾는 구조).

for target_coverage in [승리경기수, 승리경기수-1, ..., 1]:  # 큰 표본부터 시도
    candidates = []
    for depth in [1, 2, 3]:  # 조건 개수. 기본 max_depth=3 (성능 때문)
        모든 depth개 피처 조합에 대해:
            covered_wins = 이 조합이 전부 True인 승리 경기들
            if len(covered_wins) < target_coverage: continue
            covered_losses = 이 조합이 전부 True인 패배 경기들
            if len(covered_losses) > 0: continue  # 패배에 하나라도 걸리면 탈락
            candidates.append(조합)
    if candidates:
        최종 선택 = min(candidates, key=(
            -coverage,                       # 표본 큰 것 우선
            condition_priority_score(조합),   # 티어 낮은(공감가는) 것 우선 (3.3 참고)
            -diversity_score(조합),           # 서로 다른 카테고리 섞인 조합 우선
            depth,                            # 조건 개수 적은 것 우선 (동률 시 가독성)
            정렬된 조건명,                     # 최종 결정성 확보용
        ))
        return 최종 선택
    # 없으면 target_coverage 낮춰서 재시도

# depth 1~3까지 다 돌려도 못 찾으면(매우 드묾) depth 4로 한 번 더 재시도 (폴백)
# → 평소엔 depth 3까지만 돌려서 속도 확보, 예외 케이스에서만 무거운 depth 4 실행
```

**패배방지 모드**: 위와 대칭. 대조군(승리) 없이, **진 날 전체를 100% 커버하는 조건**을
동일한 depth/티어/다양성 우선순위로 탐색한다. ("당신이 [조건]일 때 직관가면 반드시
집니다. 이 조건만 피하십시오." 형태로 출력)

**완전승요**: 패배가 0이면 조건 탐색 자체를 생략하고 즉시 "조건 불필요, 그 자체로
승요"로 처리.

> 구현 참고: 동봉된 `analyzer.py`가 위 로직의 동작하는 프로토타입이다 (A그룹 전체 +
> KBO 피처 통합 완료, 패배방지 모드는 로직만 설계되어 있고 코드로는 미구현 —
> 승요 탐색 함수를 대조군 없이 돌리는 방식으로 재사용 가능).

### 3.5 희귀도 계산

```
희귀도 = 조건을 만족하는 시즌 내 경기일 수 / 시즌 전체 경기일 수
       (분모는 월요일을 제외한 시즌 기간 근사치. 정확히는 실제 경기 개최일 기준이어야 함)
```

- **조건에 KBO 피처(B그룹, 티어1)가 하나라도 섞여 있으면 계산 불가 → 희귀도 표시 생략.**
  (전체 시즌 일정 데이터가 있어야 정확히 셀 수 있기 때문. A그룹만으로 구성된 조건일 때만 계산)
- **이 희귀도는 최종 조건 선택 우선순위에 영향을 주지 않는다.** 순수하게 카드에 표시만
  하는 정보다 (3.4의 선택 로직과 무관).
- 별점 매핑 (구간값은 임의 설정 — 실제 데이터로 검증 필요, 8장 참고):

| 만족 비율 | 별점 |
|---|---|
| 0~2% | ★★★★★ |
| 2~5% | ★★★★☆ |
| 5~10% | ★★★☆☆ |
| 10~20% | ★★☆☆☆ |
| 20%+ | ★☆☆☆☆ |

> 구현 참고: `analyzer.py`의 `compute_rarity()`, `rarity_to_stars()` 참고.

### 3.6 다음 경기 추천

찾아낸 조건(A그룹 피처는 미래 날짜에 바로 재계산 가능, KBO 피처는 확정된 미래 일정
필요)을 만족하는 가장 가까운 미래 경기를 찾아 카드에 노출한다. 실제 시즌 일정 데이터가
확보된 이후 구현 (8장 참고).

## 4. 결과 카드 (4종)

디자인 레퍼런스: 동봉된 `result_cards_reference.html` (인스타 스토리 비율 9:16,
영수증/절취선 + 도장 모티프. "진지한 공문서" 톤 유지, 팀컬러는 그라디언트 배경에 반영).

공통 요소: 팀명 헤더, 영수증 스타일 본문(절취선 상하단), 판독 라벨, 판결 문장, 통계,
근거 라인, 하단 브랜드/해시태그. 도장은 원형, 회전된 형태로 배치.

### 4.1 완전승요
- 라벨: `FORCED VERDICT`
- 판결: "직관간 N경기 전부 승리. → 조건 없음. 당신 자체가 승요."
- 통계: "N전 N승 · 승률 100%"
- 조건/희귀도 없음 (해당 없음)
- 다음 경기 박스: "당장 다음 경기" / **"{응원팀}은 당신의 힘이 필요합니다."**
- 하단 문구(footer): 부분승요와 동일한 문구 사용 — 단, **"표본 3경기" 같은 구체적
  숫자는 하드코딩하지 말고 실제 값으로 바인딩할 것.** 완전승요는 애초에 "조건"이 없는
  케이스이므로, 부분승요와 문구를 그대로 복붙하지 말고 완전승요에 맞는 문구로 다시
  작성 필요 (예: 조건 언급 없는 버전으로).
- 도장: 골드, "완전승요 인증"
- 해시태그: `#완전승요 #직관필승`

### 4.2 부분승요
- 라벨: `FORCED VERDICT`
- 판결: "[조건 문장] → 무조건 승요."
- 통계: "N전 N승 · 승률 100%"
- 희귀도: "★★★★☆ (시즌 144경기 중 6경기, 4.2%)" — **라벨은 "희귀도"로 고정**
  (이전 시안에 있던 "회피지수"라는 표현은 회피 카드에서도 쓰지 않고 "희귀도"로 통일)
- 근거 라인: 각 커버된 날짜별 실제 계산/KBO 정보
- 다음 경기 박스: "다음 승요 확정처" — 조건에 맞는 다음 경기
- 도장: 빨강, "승요 공식 인증"
- 해시태그: `#승요맞음 #직관필승`

### 4.3 패배방지 모드 (회피 카드)
- 부분승요 카드와 완전히 대칭 구조.
- 라벨: `AVOIDANCE VERDICT`
- 판결: "[조건 문장] → 반드시 집니다. 피하십시오."
- 통계: "N전 N패 · 패배율 100%"
- 희귀도: 부분승요와 동일한 "희귀도" 라벨/계산식 사용 (회피지수 아님)
- 다음 경기 박스: "다음 회피 대상 경기"
- 색상: **파랑 계열** (주식 하락장 뉘앙스, `#1A56C4` 등) — 앰버 아님
- 도장: 파랑, "회피 경보 발령"
- 해시태그: `#회피경보 #패요탈출`

### 4.4 판독 보류 (표본 부족, 총 직관 3경기 미만)
- 나머지 3종과 다르게 근거/희귀도 없는 단순 레이아웃.
- 라벨: `STATUS — 판독 보류`
- 본문: "표본 부족으로 승요 여부를 판독할 수 없습니다. 현재 직관 기록: N경기 (최소 3경기 필요)"
- 진행률 바: N/3
- 밸브 문구: "승요가 되기 위해서는 수련이 필요합니다."
- 도장: 회색(무채색), "판독 보류"
- 해시태그: **`#예비승요 #수련중`** (이 순서 유지)

### 4.5 팀별 리스킨 (구현 시)
- 팀 컬러(배경 그라디언트)를 CSS 변수화하여 10개 구단 전환 가능하게.
- **구단 엠블럼/마스코트 이미지는 개발 시 별도로 삽입** (지금은 텍스트 뱃지로 대체).

## 6. 기술 스택

- **Next.js (App Router) + TypeScript** — 프론트/백엔드 분리 없이 단일 프로젝트로 진행
  (현재 스펙상 서버 로직이 거의 없어 분리 불필요. 추후 KBO 데이터 자동 갱신 등이
  필요해지면 API Routes로 같은 프로젝트 내에서 확장)
- **Tailwind CSS**
- **localStorage** — 직관 기록(팀+날짜) 저장. 로그인 없음.
  - "기록 초기화" 버튼 포함 (같은 기기에서 다른 사람이 이어서 쓸 때, 날짜를 일일이
    해제하지 않고 한 번에 리셋하기 위한 용도. 별도 경고/안내 문구 불필요)
- **html-to-image** (또는 동급 라이브러리) — 결과 카드를 클라이언트에서 캡처해 이미지로
  저장/공유. 서버사이드 이미지 생성은 하지 않음 (아래 백로그 참고)
- **Vercel** 배포

  로직 + 희귀도 계산). 패배방지 모드는 미구현이나 설계는 3.4 참고해 동일 함수 재사용 가능.

  (화면②는 구버전 카드 디자인이므로 카드 디자인은 `result_cards_reference.html` 기준으로 볼 것)
